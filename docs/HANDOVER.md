# B. 장기 플랫폼 핵심 정의

## 플랫폼 본체
동네옥션은 단순 중고마켓이 아니라 **AI가 BUY/SELL 거래 과정의 마찰을 줄이는 거래 플랫폼**으로 설계한다.

- 천원경매 = 바이럴/유입 엔진
- 일반 중고거래 = 플랫폼 본체
- AI = 판매자와 구매자 사이의 Agent 역할
- 사람 간 불필요한 직접 접촉·네고·반복질문을 줄인다.
- AI는 근거를 정리하고 보조하지만 가격/분쟁/구매의 최종 판단을 대신하지 않는다.

# F. 검색 / BUY AI Hybrid v1

## 핵심
사용자에게 `일반검색/AI검색` 모드를 고르게 하지 않는다. **검색창 하나**에서 질문 성향에 따라 자동 라우팅한다.

예:
- `아이폰15` → 일반 검색
- `아이폰15 70만원 이하` → 검색+필터
- `70만원 이하 배터리 좋은 아이폰15` → AI 조건해석+검색
- `이 둘 뭐가 달라?` → AI 비교
- `이거 비싼 편이야?` → AI+실거래 데이터
- 사진 입력 → Vision/유사상품 검색

## AI 답변 원칙
- 상품을 먼저 보여주고 AI 장문답변은 최소화
- 필터 칩으로 조건을 시각화
- 단순검색 = AI API 호출 없음
- DB/FAQ/규칙으로 해결 가능 = 외부 AI 호출 최소화
- 복합조건/비교/자연어 해석 = AI API
- 플랫폼과 무관한 범용 질문은 호출 전 차단

## 허용 범위
상품 발견·비교·구매·판매로 연결되는 질문은 허용.
예: `요즘 20대 여성이 선호하는 가을옷 트렌드는?` → 짧은 트렌드 답변 + 동네옥션 관련 상품으로 연결.
블로그 작성, 주식, 날씨 등 거래와 무관한 범용 요청은 차단.

## 3. 새상품 — 도매 API

내부:
`공급가 + 배송비 + PG/CS/반품 예상비 + 목표마진 = 최종 판매가`

사용자에게는 동네옥션 최종 판매가만 노출.

### 새상품 운영 원칙
도매 API 전체 상품을 쇼핑몰처럼 노출하지 않는다.

필터:
- 아이디어 상품
- 가성비 상품
- 시즌 상품
- 생활용품/소모품/범용상품 중심

외부 데이터와 결합:
- 계절성
- 검색량
- 트렌드
- SNS 관심
- 가격비교
- 동네옥션 내부 검색수요

`검색수요 높음 + 중고공급 부족 + 마진 확보 + CS/반품 위험 낮음` 상품 우선.

홈 노출 예:
- 이번 주 가성비 발견
- 요즘 많이 찾는 생활템
- 이번 계절에 필요한 것

검색 기본 우선순위는 **중고 우선 → 새상품 보완**.

# I. 구매예약 / 예치 / 우선협상 — KEEP

단순 무료 네고 대신 검토 중인 핵심 차별기능.

흐름:
1. BUY가 구매예약 선택
2. 예약금은 SELLER가 아니라 **플랫폼/PG에 예치**
3. SELLER 수락 → BUY가 우선협상 상대
4. 가격 + 기능검수 + 직거래조건 등을 Agent를 통해 협상
5. 합의 → 본구매
6. SELLER 거절 / 협상불발 / 시간초과 → **예치금 전액 환불**
7. 구매 성사 시 예약금은 본 결제대금에 연결/충당하는 구조 검토

## 타이머 초기안
- SELLER 수락/거절 응답: 약 2시간 후보
- 수락 후 우선협상: **24시간 초기안**
- 시간초과 → 자동 예약해제 + 전액환불 + 상품 판매상태 복귀
- 실제 데이터로 24h→12h/6h 최적화

## PG 조사 메모
토스페이먼츠 공개자료 기준:
- 일반 카드결제 공개 수수료 약 3.4% 수준(계약조건 확인 필요)
- 에스크로 추가 수수료 공개 약 0.2% 수준
- 카드 전액취소 시 카드 결제수수료 환급 안내 존재
- 에스크로 이용수수료의 취소 환급 여부/실제 C2C 계약요율은 계약 전에 반드시 재확인

**예약금 비율/금액/노쇼 몰수정책/실제 수수료는 아직 FIX 아님.** PG 견적+법무+실데이터 후 확정.

# J. 거래 엔진 v1

공통 상태 개념:
`예약 → 협상 → 결제대기 → 결제완료 → 거래중 → 검수 → 완료`

예외:
`취소 / 환불 / 분쟁`

## 직거래
결제/예치 → 장소·시간 합의 → 현장 상품확인 → 인수확인 → 구매확정 → SELLER 정산.

## 택배
결제/예치 → SELLER 발송 → 배송추적 → BUY 검수 → 구매확정 → SELLER 정산.
문제 신고 시 정산 보류 후 등록원본/거래스냅샷/배송/수령증거를 묶어 검토.

AI는 증거 정리·불일치 후보 표시까지만. 최종 분쟁판단을 자동으로 하지 않는다.

# N. 협업 방식 — 중요

사용자는 빠르게 방향·아이디어·제품 판단을 하는 강점이 있고, 좋은 아이디어가 연속해서 확장되는 경향이 있다.
AI가 해야 할 일:
- 사용자가 놓친 운영 디테일을 선제적으로 보완
- 법/비용/기술/CS/분쟁 리스크 체크
- 외부 데이터가 필요한 부분은 조사 후 답변
- 설계 간 충돌 역검증
- NOW / NEXT / LATER 범위 통제
- 방향이 명확하면 매번 `진행`을 기다리지 말고 다음 필요한 작업까지 이어서 수행
- 꾀를 부리거나 일을 줄이는 의미가 아님. **부족한 부분을 더 철저하게 채우는 역할**
- 답변은 불필요하게 길게 설명하지 말고 핵심부터 제시
