# Phase 0 — 웹 모의경매 시스템 기술명세 v1

작성일: 2026-08-14
상태: **명세 확정 / 제작 대기**
방식: **B안** — Google Sheet + Apps Script 백엔드 · 서버/계정/WebSocket 없음

---

## 0. 이 문서의 목적

Phase 0에서 검증하려는 것은 매출이 아니라 **행동**이다.

> ① 사람들이 남의 물건에 경쟁 입찰하는 걸 재미있어하는가
> ② 다음 회차에 다시 오는가
> ③ "내 물건도 올리고 싶다"고 느끼는가

따라서 결제·회원·배송·정산·채팅은 전부 범위 밖이다.
**시스템의 진짜 산출물은 낙찰가가 아니라 이벤트 로그다.**

---

## 1. 아키텍처

```
[TikTok/Shorts 광고]
        ↓ ?src=tt_a&cmp=r1
    [랜딩 index.html]
        ↓
   [예측 화면 predict.html]  ← 20:55 마감
        ↓ 21:00 자동 전환
   [LIVE 화면 live.html]
        ↓ 3초 폴링 / POST
 [Apps Script Web App (doGet/doPost)]
        ↓
   [Google Sheet — 실험 DB]
```

**원칙**
- 클라이언트 시간을 신뢰하지 않는다. **마감·연장·유효성 판정은 전부 서버(Apps Script)에서**
- 클라이언트는 표시와 요청만 한다
- 실패해도 로그는 남긴다 (거절도 데이터)

## 3. API 명세 (Apps Script Web App)

### `GET ?action=state`
현재 상태 조회. **3초 폴링.**

```json
{
  "server_time": "2026-08-16T21:03:12+09:00",
  "phase": "predict|closing|live|ended",
  "predict_close_at": "...",
  "auction_start_at": "...",
  "current_lot": {
    "lot_no": 2,
    "display_name": "AirPods 4 ANC",
    "image": "airpods.jpg",
    "current_price": 73000,
    "current_holder": "익명4821",
    "bid_count": 18,
    "close_at": "2026-08-16T21:04:30+09:00"
  },
  "lots": [ { "lot_no":1, "display_name":"...", "state":"closed", "final_price":231000 } ]
}
```

> ⚠️ `invalid_above` · `model` 은 응답에 **절대 포함하지 않는다.**
> 클라이언트로 나가는 순간 앵커가 되고, 개발자도구로 읽힌다.

### `POST action=predict`
`{ session_id, nickname, lot_no, amount, src, campaign }`

- 서버 시각이 `predict_close_at` 이후면 → `rejected: not_open`
- 동일 session_id + lot_no 중복이면 → **마지막 값으로 갱신**
- 성공/실패 모두 `events`에 기록

### `POST action=bid`
`{ session_id, nickname, lot_no, amount, src, campaign }`

**서버 검증 순서 (LockService 획득 후)**
```
1. phase == live 인가                 → not_open
2. lot.state == onair 인가            → not_open
3. server_time < lot.close_at 인가    → not_open
4. amount % 1000 == 0 인가            → bad_unit
5. amount > current_price 인가        → below_current
6. amount <= invalid_above 인가       → over_limit
7. 동일 session 1초 내 재요청 아닌가   → rate_limit
─────────────────────────────────────
   통과 → current_price 갱신, bid_count++
   close_at - server_time <= 30초면 → close_at = server_time + 30초
```

**모든 결과를 `events`에 append.** 거절도 데이터다.

### `POST action=session`
최초 방문 기록. `{ session_id, src, campaign, ua_type }` → `event_type: landing`

## 4. 화면 명세

### 4-1. 랜딩 (`index.html` — 기존)

**수정 필요**
- CTA 문구를 phase에 따라 전환
  - `predict` → **지금 예측하기 →** / `predict.html`로 이동
  - `closing` → **곧 시작합니다** / `live.html`
  - `live` → **LIVE 경매 참여 →** / `live.html`
  - `ended` → **결과 보기** / `result.html`
- URL 파라미터 `?src=` `?cmp=` 를 읽어 localStorage 저장
- 진입 즉시 `POST action=session`

### 4-2. 예측 화면 (`predict.html`)

```
닉네임  [익명4821]  (자동 생성, 수정 가능)

01  Nintendo Switch 2
    최종가 예측  [        ] 원

02  AirPods 4 ANC
    최종가 예측  [        ] 원
...

[ 예측 제출하기 ]
20:55 마감 · 가장 가까운 분께 3만원권
```

- 5개 전부 입력할 필요 없음. **1개만 해도 제출 가능**
- 제출 후 수정 가능 (마감 전까지)
- 마감되면 읽기 전용 + "예측 마감 · 21:00 LIVE 시작"

### 4-3. LIVE 화면 (`live.html`)

```
🔴 LIVE            LOT 2 / 5

      [상품 사진]

   AirPods 4 ANC

      73,000원
      현재 최고가 · 익명4821

      00:27
      남은 시간

  [ +1,000 ] [ +5,000 ] [ 직접 입력 ]

  ─────────────────────
  최근 입찰
  익명4821  73,000
  익명1102  72,000
  ─────────────────────
  NEXT → LOT 3 LEGO
```

- **3초 폴링**으로 현재가·남은 시간 갱신
- 남은 시간은 `close_at - server_time` (클라이언트 시계 미사용)
- 30초 이내면 화면 전체에 **연장 경고** 표시
- 입찰 실패 시 사유를 사람 말로: `이미 더 높은 금액이 있습니다` / `상한선을 넘었습니다`
- LOT 전환은 서버 `state` 변경을 폴링이 감지

### 4-4. 결과 화면 (`result.html`)

```
ROUND 1 결과

LOT 1  Nintendo Switch 2   1,000 → 231,000
LOT 2  AirPods 4 ANC       1,000 →  87,000
...

🎯 예측왕  익명1102 · 오차 2,000원
☕ 커피 쿠폰 10명 (닉네임 목록)

다음 회차 8/17 21:00
```

## 5. 폴링 설계

| 상황 | 주기 |
|---|---|
| 대기/예측 | 15초 |
| LIVE 일반 | 3초 |
| **마감 30초 이내** | **1.5초** |
| 종료 | 폴링 중단 |

- 탭이 백그라운드면 폴링 중단 (`visibilitychange`)
- 응답 실패 3회 연속이면 사용자에게 "연결 확인 중" 표시하고 백오프

**Apps Script 쿼터 추산**
동시 30명 × 3초 폴링 = 분당 600회. 일일 실행 한도 내이지만 **동시 50명 이상은 미검증**이므로 리허설에서 확인한다.

## 6. 리허설 계획 (광고 집행 前 필수)

| # | 항목 | 방법 | 통과 기준 |
|---|---|---|---|
| 1 | 동시 입찰 충돌 | 브라우저 10~20개에서 같은 순간 입찰 | 최고가가 하나로 확정, 중복 갱신 없음 |
| 2 | 마감 직전 입찰 | close_at 1초 전 입찰 | 30초 연장 정확히 작동 |
| 3 | 연장 반복 | 연속 3회 막판 입찰 | 매번 30초씩 연장 |
| 4 | 상한선 초과 | invalid_above + 1,000 입찰 | 거절 + 로그 기록 |
| 5 | 단위 오류 | 35,500 입찰 | bad_unit 거절 |
| 6 | 중복 요청 | 같은 버튼 연타 | rate_limit, 1건만 반영 |
| 7 | 폴링 부하 | 30탭 동시 접속 10분 | 쿼터 초과 없음, 지연 5초 이내 |
| 8 | 시계 조작 | 클라이언트 시간 변경 후 입찰 | 서버 판정으로 무효 |
| 9 | 로그 무결성 | 위 전부 수행 후 시트 확인 | 모든 이벤트 누락 없이 기록 |

**9개 전부 통과해야 광고비를 쓴다.**

## 7. 광고 소재 요건

- 길이 **10~15초**
- 훅: `Switch 2, 오늘 밤 9시 1,000원 START. 당신의 낙찰가는?`
- **소재에 "모의경매 · 실제 판매 아님" 고지 필수** (랜딩에만 있으면 광고 자체가 오인 소지)
- 소재별 `?src=` 파라미터 분리 (tt_a / tt_b / yt_a …)
- 3~4종 제작해 A/B 비교

> ⚠️ TikTok·YouTube 광고 정책은 계정 유형·지역별로 다르다.
> **집행 직전 한국 기준 공식 정책 재확인 필수.**

## 8. 측정 지표

### 퍼널
```
광고 노출 → 클릭 → 랜딩 → 예측 → LIVE 입장 → 입찰 → 2개 이상 LOT → 다음 회차
```

### 광고 소재별로 분리해서 볼 것
| 지표 | 의미 |
|---|---|
| CPC | 클릭 단가 |
| 랜딩 → 예측 전환율 | 훅이 먹혔는가 |
| 예측 → LIVE 입장률 | 리텐션 |
| LIVE → 입찰 전환율 | **핵심** |
| **1인당 참여 LOT 수** | **최중요** — 3개 이상이면 신호 |
| 최고가 갱신 횟수 | 경쟁 발생 여부 |
| 모의낙찰가 ÷ 실구매가 | 가격 발견 정도 |
| 다음 회차 재방문율 | 습관 형성 |

**싸게 데려왔지만 입찰 안 하는 소재 vs 비싸도 실제 경매하는 소재**를 구분하는 게 이 실험의 실질 목적이다.
